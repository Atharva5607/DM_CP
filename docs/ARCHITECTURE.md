# Architecture

## Layers and responsibilities

| Layer | Location | Responsibility | Knows about |
|---|---|---|---|
| Presentation | `frontend/src/pages`, `components` | Render state, collect input | Context, viz and utils only |
| Visualisation | `frontend/src/viz`, `utils/layouts.js` | SVG graph renderer (three layouts, pan and zoom, replay state) and charts | Props only; no network access |
| UI state | `frontend/src/store/NexusContext.jsx`, `PaletteContext.jsx` | Hold backend responses (or the demo snapshot), expose actions, command palette | `services/api.js`, `demo/` |
| Client API | `frontend/src/services/api.js` | The only place that builds URLs | HTTP |
| HTTP API | `backend/app/api` | Validation (Pydantic), status codes | `core.state`, services |
| Application service | `services/workspace.py` | Scenario loading, CRUD orchestration, simulation lifecycle | Domain and services |
| Domain services | `services/simulation.py`, `risk.py`, `recommendations.py`, `analytics.py`, `structure.py` | Cascade, scoring, planning, analysis | Algorithms, domain |
| Graph model | `services/graph_store.py`, `models/domain.py` | Layers, nodes, edges, dependencies, invariants | Algorithms (for views) |
| Algorithms | `backend/app/algorithms` | Pure graph and discrete-math functions | Nothing domain-specific |

Dependencies point downward only. The algorithms package imports nothing from the rest of the app, so each algorithm can be unit-tested and presented in isolation. The workspace service has no FastAPI imports, which is why the engine and its tests run without the web framework.

## Data model

| Entity | Fields (abridged) |
|---|---|
| Layer | id, name, color, description |
| Node | id, layer, label, type, criticality 1..10, capacity, zone, is_source, anchor, repair_minutes, x, y |
| Edge | id, layer, source, target, weight, repair_minutes |
| Dependency | id, provider, dependent, kind, strength (0,1], delay_min, group |
| Event | id, type, name, target_nodes, target_edges, zone, severity (0,1] |
| Simulation result | nodes (health, status, wave, arrival, path), edges, history steps, waves, layers, counts, risk |
| Recommendations | ranked actions, plan, restoration_order, repair_schedule, dispatch |
| Scenario preset | layers, nodes, edges, dependencies, events (see `data/seed.py`) |

## Key invariants

- An edge joins two nodes of the same layer. Cross-layer links are dependencies.
- Dependencies of one dependent that share a `group` are redundant alternatives.
- A node cannot depend on itself.
- Health only decreases during a simulation, which guarantees termination.
- `GraphStore.version` increments on every mutation, which keys the structure cache.

## State and concurrency

State is held in memory in one `Workspace`. FastAPI runs synchronous handlers in a thread pool, so each route takes a shared lock. Run a single worker process. `GraphStore` is the seam for adding SQLite or PostgreSQL later.

## Frontend notes

- **Layouts are pure functions** (`utils/layouts.js`): the same node coordinates feed a banded view, an isometric projection (`X = cx + (a - b) W`, `Y = cy + (a + b) H`) and a seeded force simulation. A small collision pass keeps labels from overlapping.
- **Replay without requests.** `stateAtWave(simulation, k)` rebuilds every node's health and status from the recorded propagation history, so the replay bar, hover state and edge styling all derive from one result.
- **Demo mode.** When the API is unreachable the store can switch to `demo/demo.json`, generated by `backend/scripts/export_demo.py`. The landing hero uses the same snapshot, so the home page never needs a server.
- **Motion** is CSS plus a small `useTween` hook, and all of it respects `prefers-reduced-motion`.

## Why these choices

- **Pure-Python engine.** Zero install risk, easy to read in a viewing session, simple to unit test.
- **Event-sourced replay on the client.** The backend records every propagation step, and the timeline scrubber rebuilds any wave from that history without another request. A test checks that replay equals the server's final result.
- **Simulation-verified recommendations.** Ranking by simulated risk change avoids hand-written heuristics that can drift from the model.
